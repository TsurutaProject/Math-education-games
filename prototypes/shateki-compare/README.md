# さんすう射的（比較用プロトタイプ）

> Math-education-games リポジトリの `prototypes/` にある試作です。本番の射的は遊び比べの結果を見てから `games/shateki/` に作ります。

小学校高学年向け「算数×射的」ゲームの試作です。5つのバリエーション（A〜E）を遊び比べるためのもので、完成品ではありません。
バックエンドなし・ブラウザだけで動きます（タブレット横向き 1024×768 程度と PC を想定。タッチ・マウス両対応）。

## 起動

Node.js 20 以上（v24 で確認）が必要です。

リポジトリのルートからこのフォルダに移動して実行します。

```bash
cd prototypes/shateki-compare
npm install
npm run dev
```

表示された URL（例 `http://localhost:5173/`）をブラウザで開きます。
同じ Wi-Fi のタブレットから遊ぶときは `npm run dev -- --host` で起動し、表示された `Network:` の URL を開いてください。

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発サーバー |
| `npm test` | ロジックのテスト（Vitest） |
| `npm run build` | 型チェック＋本番ビルド（`dist/` を静的ホスティングに置けば動く） |
| `npm run gen:problems` | 問題データ `src/data/problems.json` を、コースの表（`src/logic/course.ts`）に出てくる問題だけ作る。足りない問題だけを作り、今ある問題はそのまま（遊び比べ中の問題を変えないため）。全部作り直すときは `-- --all`（`-- --all 42` のようにシード指定可） |
| `npm run list:problems` | 全問題の解き方の一覧を表示（答え合わせ用） |

## ステージとマップ（#52・#53）

ステージは単元ごとの区切りです（マリオのワールドのような形）。1つのステージの中で、問題ごとに遊び方（下の A〜E）が変わります。

| ステージ | 単元 | 問題の並び |
| --- | --- | --- |
| 1 | たしざん（+ だけ） | A・A・C・D・C・E |
| 2 | ひきざん（+ −） | A・C・D・C・E |
| 3 | かけざん・わりざん（+ − × ÷） | B・C・D・C・E |

- 各ステージのはじめの問題（ステージ 1・2 は A、3 から B）で単元を伝え、そのあとの C・D・C・E がメインです。並びは `src/logic/course.ts` の表で決めます
- ステージ 3 の × は ×2・×3・×5、÷ は ÷2・÷5。÷ の札は1問に1枚までで、+ − の札はどれも ÷ の数で割り切れる数にしているので、どの順に撃っても途中の数が小数になりません
- 小数（ステージ 4）・分数（ステージ 5・6）はまだありません（#54・#55）
- 起動するとマップが出ます（展示モードでも）。左右にスクロールするか、左右の矢印でステージを選び、問題の的を撃つと始まります。的のないところを撃つと「スカッ」となり、選び直せます
- 問題の下には射撃タイプ（タップ・コルク銃・パチンコ・輪投げ）が出ます。展示モードでは問題ごとに決めた射撃タイプ、ふだんの画面では今の設定の射撃タイプです。遊び方（動く的など）の名前は出しません
- 問題の上には進み具合が出ます：挑戦済み（1発以上撃った）、緑の「クリア」（解き方を1つ以上見つけた）、山吹色の「★ クリア」（全部の解き方を見つけた）。進み具合は「つぎの人へ」で空になります
- 「つぎの問題へ」は、ステージをまたいでコースの順に進みます。最後の問題（3-5）のあとはマップにもどります
- URL の `?node=2-3`（ステージ 2 の 3 問目）で問題を指定できます。前の形の `?variant=B` などは、その遊び方がコースで最初に出てくる問題として読みます

射撃タイプは、設定パネルの「コルク銃 / パチンコ / 輪投げ」で切り替えます（URL の `?shooter=gun` / `sling` / `ring` でも指定可。前の名前の `catapult` も輪投げとして読みます。A はタップ式なので切り替えなし。D・E はコルク銃とパチンコだけ）。

展示モードでは、射撃タイプは問題ごとに `src/logic/course.ts` の表で決めたものになり、URL の `?shooter=` や設定パネルでは変えられません（#46）。いろいろな射撃タイプで自然に遊んでもらうためです。

| ステージ | 問題と射撃タイプ |
| --- | --- |
| 1 | 1-1・1-2 A タップ、1-3 C コルク銃、1-4 D コルク銃、1-5 C パチンコ、1-6 E パチンコ |
| 2 | 2-1 A タップ、2-2 C 輪投げ、2-3 D パチンコ、2-4 C コルク銃、2-5 E コルク銃 |
| 3 | 3-1 B 輪投げ、3-2 C パチンコ、3-3 D コルク銃、3-4 C 輪投げ、3-5 E パチンコ |

## 遊び方（A〜E）

- **A タップ**：的をタップすれば必ず当たる（基準）
- **B ねらう**：フィールドを押してドラッグで照準を動かし、指を離すと発射。照準は少し揺れる。外れると弾が減る。残り弾が少ないほど当たり判定がこっそり広がる
- **C リスク**：B と同じ狙い方。大きい数・× ÷ の的は小さく、一部は左右に動く。小さい数の的は大きくて止まっている。目標に届くと景品が倒れて「ゲット！」
- **D ながれる**：B と同じ狙い方。的は回転寿司のようにレーン1本の上を左から右へ流れ、右の画面外に出たら左から戻ってくる。札（的に書かれた演算子＋数）が入れ替わるのは画面外にいるときだけ。使いたい札が流れてくるのを待って撃つ
  - 問題ごとの山札に同じ札は1枚だけ。当てた札はその挑戦の中ではもう出てこない。当てずに流れていった札はまた回ってくる
  - 計算の途中でマイナスにならないよう、「−〇」は、まだ当てていない × を全部その項にかけてもマイナスにならないときだけ流す（×2 が残っていれば 〇 × 2 がいまの数以下のとき）。× ÷ は、当ててもマイナスにならず数が変わるときだけ流す。引き算の札は1問に1枚までなので、流したあとに当ててもマイナスにならない。すでに見えている札は、いまの数が変わっても倒さない
  - 届くために役立つ札がしばらく流れてこなければ、次にそれを流す（気づかれない救済）
- **E おきあがる**：B と同じ狙い方。1段に並んだ8か所の置き場所のうち、6か所に的が立っている（どこに立つかは挑戦ごとに変わる）。当てた的は C と同じように倒れ、少したつと空いている**別の場所**に新しい札の的が起き上がる。札が変わるのは当てたときと「いれかえる」を押したときだけで、時間では変わらない
  - 左下の「いれかえる」を押すと、一番長く立っている的が静かに沈み、別の場所に新しい札の的が起き上がる。弾は減らない
  - 起き上がる札は、出してよい札の中からランダムに選ぶ（答えに誘導しない。D のような救済はない）。山札・当てた札がもう出てこないこと・マイナスにならない札だけ出すことは D と同じ。起き上がりきるまで（0.35秒）は当たらない

射撃タイプ（B〜E）：

- **コルク銃**：上の B の説明どおり。照準を合わせて離すと、その位置に一瞬で当たる
- **パチンコ**：フィールドのどこでも押して、うしろに引っ張り、離すと反対の向きに弾が飛ぶ（引っ張って狙う形）。弾には速さがあるので、動く的は先を読んで撃つ。弾は最初に触れた的で止まる。全方向に発射可能で、左右の壁ではね返る（設定で切替）。上下の端では反射せず外れになる。水平発射などで飛び続ける場合は3秒で外れになる。下端へ出た際の「スカッ」と外れ音は0.1秒遅らせる。点線のガイドで飛ぶ向きがわかる。短く引いただけでは撃たない。B の補正（当たり判定を広げる）と照準の揺れ（パチンコでは向きが少しぶれる）も同じように効く。パチンコでは的を1段に並べる
- **輪投げ**：パチンコと同じく、どこでも押してうしろに引っ張り、離すと輪が山なりに飛ぶ。**長く引くほど奥、引く向きで左右**が決まる。輪は札や棒に当たるとはね返り、**床に落ちたときに棒を囲んでいれば入り**（途中で当たっても外れにしない）。入った棒の上に足した数が出る。同じ棒には1回しか入らない（もう一度入ると「おなじ ぼうは 1かいだけ」と出て、弾は1つ減る）。引っ張っている間は山なりの道すじと落ちる場所が出る（設定で隠せる）

共通：0 から始めて、当てた順に式を書いていきます。かけ算は直前の数にだけかかります（小学4年で習う「かけ算を先に計算する」順序）。たとえば +5 → +10 → ×2 は `5 + 10 × 2 = 25` で、`(5 + 10) × 2 = 30` にはなりません。目標と同じになった瞬間にクリア → 「解き方ずかん」。弾切れは「おしい！あと〇」→ すぐやり直し。

## ヒント（#57）

遊んでいる画面の右下、「さいしょから」の左隣の「💡 ヒント」を押すと、図鑑にまだない解き方を1つ選び、それに向かうための**つぎに当てる的だけ**を3秒光らせます（考える余地を残すため）。

- 途中で押したときは、いまの式の続きで行ける、まだ見つけていない解き方から選びます。行ける解き方がない（もう届かない・続きの解き方は全部見つけた）ときは、的を光らせずに「さいしょから」のボタンを3秒強調します
- 押すたびに道が変わらないよう、前に選んだ解き方にまだ行けるあいだは、同じ解き方を続けます
- D・E で選んだ的が画面に出ていないときは、出てきたときから3秒光ります。D・E はいまの数をマイナスにする札を出さないので、マイナスを通らない道だけから選びます
- 1発撃つと、前のヒントの光は消えます
- 回数の制限はありません。その問題の解き方を全部見つけたら、ボタンは押せなくなります
- ヒントを使って見つけた解き方も、図鑑では区別しません（使ったかはログの `hint` で見ます）

## 設定パネル（右上の ⚙️）

射撃タイプ・ステージ・問題の切り替え、パチンコの弾の速さ・ガイドの長さ・壁ではね返るか、輪投げの飛んでいる時間・落ちる場所を見せるか、B の補正の強さ、照準の揺れ幅、C の的の大きさ・移動速度・C にも補正を使うか、D のレーンの速さ・画面に出る的の数・救済を使うか・救済までの秒数、E の立っている的の数・起き上がるまでの秒数、式の表示、効果音、ログのダウンロード／消去。
設定はブラウザに保存されます（「設定を元にもどす」で初期値）。

## 展示モード（issue #31）

展示では、子どもが切り替えや設定を触れないように、URL の最後に `&mode=exhibit` を付けて開きます。

```
http://localhost:5173/?mode=exhibit
```

- ⚙️ とタイトルの「試作」が消えます。マップと「マップへ」のボタンはふだんと同じように出るので、子どもは好きな問題を選べます（どの順に選んだかはログに残ります）
- 射撃タイプは問題ごとに決まっています（上の表）。URL の `shooter` と保存した設定の射撃タイプは使いません。URL に `shooter` を付けて開いても、URL から消えます
- 一度 `mode=exhibit` で開くとブラウザが覚えるので、再読み込みしても、タイトルからホームにもどって射的に入り直しても展示モードのままです。やめるときは URL に `?mode=normal` を付けて開きます（「展示モードを外した画面」はこの開き方です）
- 上のバーのタイトル「さんすう射的」を押すと、プラットフォームのホームにもどります（#49。分ケーキと同じく確認は出しません。ログは残ります）
- **スタッフ用の設定パネル**：`Ctrl + Shift + S`（Mac も Control キー）を押し、確認で「OK」を押すと開きます。中身は「遊ぶ人（つぎの人へ）」「あそぶもの（ステージ・問題。射撃タイプはいまの問題のものを出すだけで、切り替えられません）」「ログ」だけです。ログはダウンロードだけで、展示中に誤って消さないよう「ログを消去」は出しません
- 弾の速さなどの細かい調整は、展示の前に、展示モードを外した画面で行います。設定はブラウザに保存されるので、展示モードでもそのまま使われます
- **遊ぶ人が替わるたびに、スタッフ用パネルの「つぎの人へ」を押します。** ログの人の区切りになり、図鑑とマップの進み具合が空になって、マップ（ステージ 1）にもどります。押し忘れると、2人分が1人の記録になります

展示の前に確かめること：

- [ ] 細かい設定を調整した（展示モードを外した画面で）
- [ ] 前のログをダウンロードしてから「ログを消去」した（展示モードを外した画面で）
- [ ] 展示に使うブラウザで `Ctrl + Shift + S` からスタッフ用パネルが開く（ブラウザによっては、同じキーを別の機能に使っていることがあります。例：Firefox のスクリーンショット）
- [ ] 毎回**同じ URL**（ホスト・ポート番号も同じ）で開く。設定とログは URL ごとに別に保存されるため、ポート番号が変わると前の設定・ログが見えなくなります
- [ ] ブラウザを全画面表示にする（アドレスバーを触られにくくなります）
- [ ] ゲームを開いているタブは1つだけ
- [ ] 最初の人が遊ぶ前に「つぎの人へ」を押した（前の人の記録と分けるため）

## ログ（issue #20）

遊んだ記録をブラウザに保存し、設定パネル（展示モードではスタッフ用パネル）の「JSONをダウンロード」で取り出します。サーバーには送りません。個人情報は記録しません。
項目の説明と、データ分析班の要望との対応は [docs/LOGGING.md](docs/LOGGING.md) にまとめています。

- ダウンロードしたファイルには、**挑戦ごとのまとめ（`attempts`、1回の挑戦 = 1行）** と、**時系列のすべてのイベント（`events`）** が入ります。表にするときは `attempts` を使うと楽です
- 人の区切りは `playerId` です。スタッフ用パネルの「つぎの人へ」でだけ変わります（再読み込みでは変わりません）。起動ごとの `sessionId`、パソコン（ブラウザ）ごとの `deviceId` も入ります
- ログは localStorage に保存されるので、再読み込みしても消えません（端末ごと・ブラウザごと・URL のホストとポートごとに別）。保存の量は設定パネルに「保存の量（目安）」として出ます。8割を超えたり、保存に失敗したりしたら、パネルと画面の右上に赤い「● ログ」が出ます。出たらすぐダウンロードしてください
- 同じゲームは**1つのタブ**で開いてください（ほかのタブの保存は読み直しますが、ほぼ同時に保存すると片方が消えることがあります）
- 文化祭で使う前後に、ダウンロードしてから「ログを消去」してください（展示モードを外した画面で）

## 問題データの形式

```json
{
  "id": "std-1-1", "set": "standard", "stage": 1, "goal": 40, "shots": 3,
  "targets": [{ "id": "t1", "op": "+", "value": 10 }, ...]
}
```

`op` は `+` `-` `*` `/`。C 用（`set: "risk"`）の的には `size`（`L`/`M`/`S`）と `moving` が付きます。D 用（`set: "lane"`）と E 用（`set: "rise"`）は形は同じで、同じ札（`op` と `value` が同じ的）を2枚入れません。
手で問題を書き換えたら `npm test` を実行してください。「解き方が2つ以上」「C は安全な道がある」「D・E は同じ札がない」「D・E の札の出し方で全部の解き方が撃てる」「ステージごとの演算（1 は + だけ、2 は + −、3 は × と ÷ がある）」「÷ は1枚までで、+ − の札はどれも割り切れる」「コースの表の問題がそろっている」などの条件を満たさないとテストが落ちます。

## 音声・画像素材の置き場所（issue #12）

`public/sounds/` に効果音、`public/bgm/` にBGM、`public/images/` に画像をまとめます。素材を追加後はページを再読み込みしてください。効果音は最初の操作で読み込みを開始し、未配置・読み込み中・再生できない形式の場合は従来の合成音を使います。重い命中（hit-heavy）・C のクリア（clear-big）の音がなければ共通音（hit・clear）、共通音もなければ合成音になります。

| ファイル名（拡張子を除く） | 場面 |
| --- | --- |
| shot | コルク銃の発射 |
| hit / hit-heavy | 命中（hit-heavy があればそちらを使う。全部のバリエーションで同じ） |
| miss | 外れ |
| sling | パチンコの発射 |
| ring | 輪投げの輪を投げる |
| thud | 輪投げの外れ（床に落ちた） |
| clear / clear-big | クリア / Cのクリア |
| out | 弾切れ |
| rise | E の的が起き上がる |

音声は `.mp3` → `.ogg` → `.wav` の順に読み込み可能なものを使用。例：`public/sounds/shot.mp3`。同じ名前の形式をすべて用意する必要はありません。未配置のときは、開発サーバー（npm run dev）では 404 ではなくページの HTML が返り、公開先によっては 404 になります。どちらの場合も、読み込めない形式として次の形式を試し、どれもなければ合成音で続けます。

BGMは `public/bgm/game.mp3`（ogg/wavも可）。設定でオンにすると、最初の操作後にループ再生します。既定はオフ・音量25%。効果音とは別に切り替えられ、タブが非表示になると停止、戻ると最初から再開します。BGM未配置時は無音です。

画像は `public/images/` 以下に用途ごとのフォルダ（例：`prizes/`、`backgrounds/`）を作れます。PNG・WebP・SVG等を使用し、コードでは `import.meta.env.BASE_URL + 'images/prizes/example.webp'` のように参照します。配置だけでは現在の絵文字・画面画像は差し替わりません。差し替える画面を決めてから参照を追加してください。

素材受け渡し時にはファイル名、用途、作者、配布元URL、ライセンス、必要なクレジットを `public/CREDITS.md` に記録してください。形式・容量の上限は未確定です。暫定目安は効果音1つ500KB以内、BGM5MB以内、画像1枚1MB以内とし、音量は実機でそろえてください（自動正規化はしません）。
