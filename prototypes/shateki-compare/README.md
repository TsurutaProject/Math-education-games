# さんすう射的（比較用プロトタイプ）

> Math-education-games リポジトリの `prototypes/` にある試作です。本番の射的は遊び比べの結果を見てから `games/shateki/` に作ります。

小学校高学年向け「算数×射的」ゲームの試作です。4つのバリエーション（A/B/C/D）を遊び比べるためのもので、完成品ではありません。
バックエンドなし・ブラウザだけで動きます（タブレット横向き 1024×768 程度と PC を想定。タッチ・マウス両対応）。

## 起動

Node.js 20 以上（v24 で確認）が必要です。

リポジトリのルートからこのフォルダに移動して実行します。

```bash
cd prototypes/shateki-compare
npm install
npm run dev
```

表示された URL（例 `http://localhost:5173/`）をブラウザで開きます。
同じ Wi-Fi のタブレットから遊ぶときは `npm run dev -- --host` で起動し、表示された `Network:` の URL を開いてください。

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発サーバー |
| `npm test` | ロジックのテスト（Vitest） |
| `npm run build` | 型チェック＋本番ビルド（`dist/` を静的ホスティングに置けば動く） |
| `npm run gen:problems` | 問題データ `src/data/problems.json` を作り直す（`-- 42` のようにシード指定可） |
| `npm run list:problems` | 全問題の解き方の一覧を表示（答え合わせ用） |

## 遊び方とバリエーション

画面上部のボタンで切り替えます。URL の `?variant=A` / `B` / `C` / `D` でも指定できます。
B・C・D は、その右の「コルク銃 / パチンコ / カタパルト」で射撃タイプも切り替えられます（URL の `?shooter=gun` / `sling` / `catapult` でも指定可。A はタップ式なので切り替えなし。D はコルク銃とパチンコだけ）。

- **A タップ**：的をタップすれば必ず当たる（基準）
- **B ねらう**：フィールドを押してドラッグで照準を動かし、指を離すと発射。照準は少し揺れる。外れると弾が減る。残り弾が少ないほど当たり判定がこっそり広がる
- **C リスク**：B と同じ狙い方。大きい数・×2 の的は小さく、一部は左右に動く。小さい数の的は大きくて止まっている。目標に届くと景品が倒れて「ゲット！」
- **D ながれる**：B と同じ狙い方。的は回転寿司のようにレーン1本の上を左から右へ流れ、右の画面外に出たら左から戻ってくる。札（的に書かれた演算子＋数）が入れ替わるのは画面外にいるときだけ。使いたい札が流れてくるのを待って撃つ
  - 問題ごとの山札に同じ札は1枚だけ。当てた札はその挑戦の中ではもう出てこない。当てずに流れていった札はまた回ってくる
  - 計算の途中でマイナスにならないよう、「−〇」は 〇 がいまの数以下のときだけ、×2 はいまの数が 0 でないときだけ流す。いまの数が変わって引けなくなった札は、その場で灰色になって倒れる
  - 届くために役立つ札がしばらく流れてこなければ、次にそれを流す（気づかれない救済）

射撃タイプ（B・C・D）：

- **コルク銃**：上の B の説明どおり。照準を合わせて離すと、その位置に一瞬で当たる
- **パチンコ**：フィールドのどこでも押して、うしろに引っ張り、離すと反対の向きに弾が飛ぶ（引っ張って狙う形）。弾には速さがあるので、動く的は先を読んで撃つ。弾は最初に触れた的で止まる。左右の壁ではね返る（設定で切替）。点線のガイドで飛ぶ向きがわかる。短く引いただけでは撃たない。B の補正（当たり判定を広げる）と照準の揺れ（パチンコでは向きが少しぶれる）も同じように効く。パチンコでは的を1段に並べる
- **カタパルト**：パチンコと同じく、どこでも押してうしろに引っ張り、離すと飛ぶ。**長く引くほど遠く（奥の棚）、短く引くほど近く（手前の棚）に落ちる**。引く向きで左右が決まる。弾は山なりに飛んで手前の的を飛び越え、**着地した点**で当たりを決める（的は2段のまま）。引っ張っている間は山なりの道すじと着地点、ひっぱりの強さのゲージが出る（設定で着地点を隠せる）。飛んでいる時間があるので、動く的は先を読んで撃つ

共通：0 から始めて、当てた的の演算を今の数にかけていきます。目標と同じになった瞬間にクリア → 「解き方ずかん」。弾切れは「おしい！あと〇」→ すぐやり直し。

## 設定パネル（右上の ⚙️）

バリエーション・射撃タイプ・ステージ・問題の切り替え、パチンコの弾の速さ・ガイドの長さ・壁ではね返るか、カタパルトの飛んでいる時間・着地点を見せるか、B の補正の強さ、照準の揺れ幅、C の的の大きさ・移動速度・C にも補正を使うか、D のレーンの速さ・画面に出る的の数・救済を使うか・救済までの秒数、式の表示、効果音、ログのダウンロード／消去。
設定はブラウザに保存されます（「設定を元にもどす」で初期値）。

## ログ

イベント（問題の開始・発射・数の変化・クリア・弾切れ・さいしょから）を時刻つきで記録し、設定パネルから JSON でダウンロードできます。
個人情報は記録しません。各イベントに `variant` / `shooter`（`tap` / `gun` / `sling` / `catapult`）/ `stage` / `problemId` / `attemptId`（1回の挑戦ごとのランダム ID）が入ります。
ログはブラウザの localStorage に保存されるので、再読み込みしても消えません（端末ごと・ブラウザごとに別）。文化祭で使う前後に「ログを消去」してください。

主な項目：
- `shot.aim` … 狙った位置（フィールド左上 0,0 〜 右下 1,1）
- `shot.assist` … そのときの当たり判定の倍率（1 = 補正なし）
- `shot.reachableAfter` / `value_change.reachable` … その時点で残りの弾で届くか
- `shot.launch` … パチンコ・カタパルトのときだけ。飛ばした角度（真上 0、右が +）、引っ張った長さ、飛んでいた時間。パチンコは壁ではね返った回数、カタパルトは着地点（0〜1）
- `clear.key` … 解き方の正規化キー、`clear.isNew` … 図鑑にとって新しい発見か

## ファイル構成

```
src/logic/      描画に依存しないロジック（すべて Vitest でテスト）
  normalize.ts    解き方の正規化キー（図鑑の同一判定）
  solver.ts       撃ち方の全列挙・途中から届くかの判定
  game.ts         1発撃ったときの状態遷移
  hit.ts          的の配置・動き・当たり判定・補正
  sling.ts        パチンコの弾の動き・はね返り・当たり・ガイド線
  catapult.ts     カタパルトの引っ張り→飛ぶ距離・着地点・山なりの道すじ
  lane.ts         D のレーン（流れる位置・札の選び方・マイナスにしない・救済）
  generator.ts    問題の生成と条件チェック
  zukan.ts / log.ts / problems.ts / ops.ts / types.ts
src/data/problems.json   問題データ（standard = A/B 用、risk = C 用、lane = D 用）
src/ui/         React の画面
scripts/        問題の生成・一覧スクリプト
docs/ASSUMPTIONS.md   仮置きした仕様とその理由
docs/PLAYTEST.md      遊び比べのチェック項目
```

## 問題データの形式

```json
{
  "id": "std-1-1", "set": "standard", "stage": 1, "goal": 40, "shots": 3,
  "targets": [{ "id": "t1", "op": "+", "value": 10 }, ...]
}
```

`op` は `+` `-` `*` `/`。C 用（`set: "risk"`）の的には `size`（`L`/`M`/`S`）と `moving` が付きます。D 用（`set: "lane"`）は形は同じで、同じ札（`op` と `value` が同じ的）を2枚入れません。
手で問題を書き換えたら `npm test` を実行してください。「解き方が2つ以上」「C は安全な道がある」「D は同じ札がない」などの条件を満たさないとテストが落ちます。
