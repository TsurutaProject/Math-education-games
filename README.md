# さんすう射的（比較用プロトタイプ）

小学校高学年向け「算数×射的」ゲームの試作です。3つのバリエーション（A/B/C）を遊び比べるためのもので、完成品ではありません。
バックエンドなし・ブラウザだけで動きます（タブレット横向き 1024×768 程度と PC を想定。タッチ・マウス両対応）。

## 起動

Node.js 20 以上（v24 で確認）が必要です。

```bash
npm install
npm run dev
```

表示された URL（例 `http://localhost:5173/`）をブラウザで開きます。
同じ Wi-Fi のタブレットから遊ぶときは `npm run dev -- --host` で起動し、表示された `Network:` の URL を開いてください。

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発サーバー |
| `npm test` | ロジックのテスト（Vitest） |
| `npm run build` | 型チェック＋本番ビルド（`dist/` を静的ホスティングに置けば動く） |
| `npm run gen:problems` | 問題データ `src/data/problems.json` を作り直す（`-- 42` のようにシード指定可） |
| `npm run list:problems` | 全問題の解き方の一覧を表示（答え合わせ用） |

## 遊び方とバリエーション

画面上部のボタンで切り替えます。URL の `?variant=A` / `B` / `C` でも指定できます。
B・C は、その右の「コルク銃 / パチンコ」で射撃タイプも切り替えられます（URL の `?shooter=gun` / `sling` でも指定可。A はタップ式なので切り替えなし）。

- **A タップ**：的をタップすれば必ず当たる（基準）
- **B ねらう**：フィールドを押してドラッグで照準を動かし、指を離すと発射。照準は少し揺れる。外れると弾が減る。残り弾が少ないほど当たり判定がこっそり広がる
- **C リスク**：B と同じ狙い方。大きい数・×2 の的は小さく、一部は左右に動く。小さい数の的は大きくて止まっている。目標に届くと景品が倒れて「ゲット！」

射撃タイプ（B・C）：

- **コルク銃**：上の B の説明どおり。照準を合わせて離すと、その位置に一瞬で当たる
- **パチンコ**：フィールドのどこでも押して、うしろに引っ張り、離すと反対の向きに弾が飛ぶ（引っ張って狙う形）。弾には速さがあるので、動く的は先を読んで撃つ。弾は最初に触れた的で止まる。左右の壁ではね返る（設定で切替）。点線のガイドで飛ぶ向きがわかる。短く引いただけでは撃たない。B の補正（当たり判定を広げる）と照準の揺れ（パチンコでは向きが少しぶれる）も同じように効く。パチンコでは的を1段に並べる

共通：0 から始めて、当てた的の演算を今の数にかけていきます。目標と同じになった瞬間にクリア → 「解き方ずかん」。弾切れは「おしい！あと〇」→ すぐやり直し。

## 設定パネル（右上の ⚙️）

バリエーション・射撃タイプ・ステージ・問題の切り替え、パチンコの弾の速さ・ガイドの長さ・壁ではね返るか、B の補正の強さ、照準の揺れ幅、C の的の大きさ・移動速度・C にも補正を使うか、式の表示、効果音、ログのダウンロード／消去。
設定はブラウザに保存されます（「設定を元にもどす」で初期値）。

## ログ

イベント（問題の開始・発射・数の変化・クリア・弾切れ・さいしょから）を時刻つきで記録し、設定パネルから JSON でダウンロードできます。
個人情報は記録しません。各イベントに `variant` / `shooter`（`tap` / `gun` / `sling`）/ `stage` / `problemId` / `attemptId`（1回の挑戦ごとのランダム ID）が入ります。
ログはブラウザの localStorage に保存されるので、再読み込みしても消えません（端末ごと・ブラウザごとに別）。文化祭で使う前後に「ログを消去」してください。

主な項目：
- `shot.aim` … 狙った位置（フィールド左上 0,0 〜 右下 1,1）
- `shot.assist` … そのときの当たり判定の倍率（1 = 補正なし）
- `shot.reachableAfter` / `value_change.reachable` … その時点で残りの弾で届くか
- `shot.launch` … パチンコのときだけ。飛ばした角度（真上 0、右が +）、引っ張った長さ、飛んでいた時間、壁ではね返った回数
- `clear.key` … 解き方の正規化キー、`clear.isNew` … 図鑑にとって新しい発見か

## ファイル構成

```
src/logic/      描画に依存しないロジック（すべて Vitest でテスト）
  normalize.ts    解き方の正規化キー（図鑑の同一判定）
  solver.ts       撃ち方の全列挙・途中から届くかの判定
  game.ts         1発撃ったときの状態遷移
  hit.ts          的の配置・動き・当たり判定・補正
  sling.ts        パチンコの弾の動き・はね返り・当たり・ガイド線
  generator.ts    問題の生成と条件チェック
  zukan.ts / log.ts / problems.ts / ops.ts / types.ts
src/data/problems.json   問題データ（standard = A/B 用、risk = C 用）
src/ui/         React の画面
scripts/        問題の生成・一覧スクリプト
docs/ASSUMPTIONS.md   仮置きした仕様とその理由
docs/PLAYTEST.md      遊び比べのチェック項目
```

## 問題データの形式

```json
{
  "id": "std-1-1", "set": "standard", "stage": 1, "goal": 40, "shots": 3,
  "targets": [{ "id": "t1", "op": "+", "value": 10 }, ...]
}
```

`op` は `+` `-` `*` `/`。C 用（`set: "risk"`）の的には `size`（`L`/`M`/`S`）と `moving` が付きます。
手で問題を書き換えたら `npm test` を実行してください。「解き方が2つ以上」「C は安全な道がある」などの条件を満たさないとテストが落ちます。
